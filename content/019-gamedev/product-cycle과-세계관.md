# 5-사이클 1인 게임 개발 마스터 플랜

> WPF 3년차 개발자의 1인 게임 개발 로드맵. **5개의 게임**을 점진적으로 규모를 키워가며 *모두 출시까지 완수*하고, 그 다섯 작품이 **하나의 세계관**을 공유한다.

---

## 1. 핵심 전략

### 1.1 왜 "5개 출시" 인가
'출시까지 완수한 게임'을 여러 차례 경험하는 것이 게임 개발 실력 향상의 가장 빠른 길. 따라서 각 사이클의 학습 목표는 *완성도 있는 코드*가 아니라 **"출시"라는 행위 그 자체** — 스토어 등록, 연령 등급, 정책 검토, 트레일러, 스크린샷, 빌드 파이프라인.

### 1.2 사이클 구조
- **5개 사이클**, 점진 증가
- 각 사이클은 *반드시 출시까지 완수*
- 도구: Unity + Claude Code + Unity MCP

### 1.3 세계관 공유 — 서사적 공유 (A 옵션)
- 5개 게임 모두 **동일 시공간**에서 일어남 (같은 도시, 같은 시대, 같은 지역)
- NPC·장소·사건이 작품 간 재등장
- 출시 순서 ≠ 게임 내 시간 순서 (마블 시네마틱 유니버스 방식)
- 컨셉: **"한 도시의 5개 시점"** — 사이클이 진행될수록 도시의 *전투 중심*으로 줌인

### 1.4 의도적 연결 사례
> 1번 사이클 약초꾼이 채집·가공한 *영초 첨가제* → 2번 사이클 대장장이가 *연금술적 강화*에 사용 → 5번 사이클 공대장이 출정 전 보급에서 그 강화 무기를 NPC에게 지급

## 2. 시각·장르 결정

### 2.1 시각 양식
| 항목 | 결정 |
|---|---|
| 양식 | **쿼터뷰 픽셀** |
| 전투 | **실시간** (턴제 SRPG 아님) |
| 카메라 | 90도 4방향 회전 + 줌 |
| 정체성 | "전장을 내려다보는 사령관 시점" |

### 2.2 톤·장르
**(라) 동양 베이스 + 서양 판타지 요소 약간** — Octopath Traveler / Sekiro 톤

### 2.3 아트 파이프라인
- **AI 픽셀 생성** (SDXL/Flux + 픽셀 LoRA)
- 동양 판타지 픽셀 학습량 부족 → **하이브리드 톤 + ControlNet/참조 이미지** 결합
- (옵션) 1번 사이클 시작 전 한국적 픽셀 LoRA 자체 파인튜닝 1~2주 가능

### 2.4 정신적 선조작
Pillars of Eternity / Baldur's Gate (RTwP), Final Fantasy XII 갬빗, Dragon Age: Origins 전술, Children of Morta + WoW 공대 메커닉

## 3. 세계관 뼈대

### 3.1 무대 — "그 도시"
- **성격**: 변방의 군사 요충지 + 모험가 거점
- 산맥에 인접, 던전·요괴 출몰. 군문·모험가 길드·대장간이 공존
- 모티프 참고: 조선의 변경 군영, 명나라 변경 도시
- *이름 미정* (추후 결정)

### 3.2 마법/힘 체계
- **기(氣) + 마나 하이브리드**
- 동양 베이스(기·도·음양) 위에 서양식 마나가 부분적으로 공존
- 메커니컬 변용 자유도 ↑, 톤 일관성 ↑

### 3.3 종족 구도
- **인간 + 동양 신수/요괴**
- 신수: 백호, 이무기, 까마귀
- 요괴: 구미호, 도깨비
- 1인 개발 부담 적정 + 동양 판타지 매력 극대화

### 3.4 직업 카테고리

#### 전투 직업군 (비율 4 / 3 / 3, 트리니티)

| 카테고리 | 비율 | 역할 매핑 | 직업 (예시) |
|---|---|---|---|
| **기(氣) 사용자** | 4 | 탱/딜 | 무인, 검사, 권법가, 궁사, 방패무사 |
| **마나/주술 사용자** | 3 | 힐/딜/제어 | 술사, 주법사, 음양사, 부적사 |
| **신수(神獸) 활용자** | 3 | 탱/딜/원거리 | 신수변신자, 신수소환자, 빙의자 |

탱/힐/딜 트리니티 명확 (WoW식). 일부 직업은 하이브리드 가능.

#### 비전투 직업군 — **기예자(技藝者)**
- 약초꾼, 대장장이, 연금술사, 부적 제작자 등
- **공격대 일원이 아님**. 후방 지원망(보급, 강화, 약품)에 위치
- 1번/2번 사이클의 주인공 카테고리

## 4. 사이클 매핑

| # | 직업 | 장르 | 학습 핵심 기술 | 5번 시뮬 재사용 자산 |
|---|---|---|---|---|
| 1 | **의원 수습생** (기예자) | 필드 채집 타임어택 (Steam PC) — 작은 필드 자유 이동, 시간제한 내 약초 수집 | Steam 출시 파이프라인 + Unity 기본 + 오행 수치 데이터 모델 | 오행 수치 시스템, 약초 DB 기초, 세계관 분위기 |
| 2 | **약초꾼 + 의원** (기예자) | 음양오행 진단·처방 경영 시뮬 | 환자 AI·시간 시스템·조합·처방 로직 | 환자 상태 데이터 구조, 약초/처방 DB |
| 3 | **대장장이** (기예자) | 경영·제작 시뮬 (연금술 결합) | 자원·인벤토리·제작 시스템 | 장비 데이터 모델, 연금술적 강화 시스템 |
| 4 | **소규모 부대장** | 6~8인 실시간 전술 RPG (5/8인 듀얼) | 명령 큐, 보스 기믹 1~2개, **인카운터 인원 스케일링 시스템** | 시스템 ~70% 사전 검증 |
| 5 | **공대장** | 쿼터뷰 픽셀 실시간 공격대 전술 RPG (10/20인 듀얼) | 전체 통합 + 인원 스케일링 확장 + 폴리싱 | — |

### 4.1 사이클 1: 필드 채집 타임어택
- **정체성**: 의원 수습생 시절. 2번 의원 시뮬레이터의 직접 예고편
- **메커닉 핵심**: 작은 필드에서 WASD 자유 이동 → 시간제한 내 필요한 약초 수집 → 환자 수치 정상화
- **조작**: WASD + 컨트롤러 지원. 약초에 닿으면 자동 수집.
- **MVP 오행**: 목/화/수 + 음양 (토·금은 업데이트). 오행 블렌딩 방식은 프로토타입 이후 확정.
- **플랫폼**: **Steam** (사이클 1부터 Steam 파이프라인 학습. 모바일 없음)
- **학습 목표**: Steam 출시 파이프라인 최초 학습 (Steamworks, 스토어 페이지, Achievements, 리뷰 대응)
- 상세: [[content/019-gamedev/cycle-01-약초꾼-시뮬레이터.md]]

### 4.2 사이클 2: 의원 시뮬레이터
- **정체성**: 수습 수료 후 본격 의원 운영. 1번의 캐주얼 루프를 풀 시뮬레이션으로 확장
- **메커닉 핵심**: 음양오행 진단 → 약초 채집/구매 → 처방 조합 → 치료 결과. 하루 시간 시스템, 네임드 환자 스토리
- **연결**: 3번 대장장이가 만든 약재 용기/도구를 의뢰·구매하는 방식으로 연결

### 4.3 사이클 4 → 5 점프 완화
4번 사이클에서 **인카운터 인원 스케일링 시스템**을 *작게* 도입(5인/8인 듀얼 모드) → 5번에서 같은 시스템을 10/20인으로 확장. 가장 위험한 시스템을 한 사이클 일찍 검증.

### 4.4 사이클 5: 공대장 시뮬레이터
- **장르**: 쿼터뷰 픽셀 실시간 공격대 전술 RPG (RTT/RTwP)
- **인원 스케일**: 10인 + 20인 듀얼 (WoW 10인/25인 모드 패턴)
- **공대원 후보 풀**: 최소 30~40명
- **출정 준비 단계**: 1번 약초꾼의 약품 + 2번 대장장이의 무기 시스템 활용 → *시리즈 팬에게 강력한 관계성 제공*
- **정체성 변화**: WoW의 1인칭 몰입 포기, 대신 **"공대장 본질에 집중"** — 전장을 내려다보며 NPC 공대원에게 실시간 명령

## 5. 미결 사항

### 5.1 우선순위 중간 (각 사이클 진입 시 확정)
- 도시 이름
- 탱 직업 추가 (현재 3개 → 4~5개 필요)
- 정치/세력 구도 (왕조? 무인 정권? 길드 연합?)
- 기·마나의 자원 비용 모델 (마나/기력/스태미나)
- 인카운터 인원 스케일링 알고리즘 설계 (선형 vs 비선형)
- 출시 인프라 사전 준비 (Steam Direct $100, GRAC) — Google Play/Apple은 사용 안 함

### 5.2 우선순위 낮음 (사이클 도달 시)
- 공대장 시뮬 메타 진행 모델 (로그라이크 vs 캠페인 vs 하이브리드)
- 공대원 후보 풀의 캐릭터화 깊이 (Darkest Dungeon 식 vs Battle Brothers 식 vs 명명만)
- 메타 브랜딩 (스튜디오명, 로고 모티프, 공통 UI 사인)
- 사이클 3 장르 확정 (카드 매칭 vs 스텔스)
- 사이클 2~5의 플랫폼 확정 (모바일 vs 스팀)
