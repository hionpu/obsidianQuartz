# HTTP/HTTPS와 SSL/TLS, OSI 7계층 네트워크 기초

## HTTP vs HTTPS

**HTTP (HyperText Transfer Protocol)**는 웹에서 데이터를 주고받기 위한 기본 프로토콜입니다. 반면 **HTTPS (HTTP Secure)**는 HTTP에 보안 계층을 추가한 것입니다.

### 주요 차이점

**보안성**
- HTTP: 평문으로 데이터 전송, 제3자가 쉽게 도청 가능
- HTTPS: 암호화된 데이터 전송, 도청 방지

**포트**
- HTTP: 기본 포트 80
- HTTPS: 기본 포트 443

**성능**
- HTTP: 암호화 오버헤드 없음
- HTTPS: 초기 SSL/TLS 핸드셰이크로 약간의 지연, 하지만 현대에는 미미함

**신뢰성**
- HTTP: 데이터 무결성 보장 없음
- HTTPS: 데이터 변조 탐지 가능

## SSL/TLS 동작 원리

SSL/TLS는 공개키 암호화와 대칭키 암호화를 조합하여 작동합니다.

### 핸드셰이크 과정

1. **Client Hello**: 클라이언트가 지원하는 암호화 방식 목록을 서버에 전송
2. **Server Hello**: 서버가 선택한 암호화 방식과 인증서를 클라이언트에 전송
3. **인증서 검증**: 클라이언트가 서버 인증서의 유효성을 확인
4. **키 교환**: 클라이언트가 대칭키를 생성하고 서버의 공개키로 암호화하여 전송
5. **암호화 통신 시작**: 양쪽 모두 대칭키를 사용하여 데이터 암호화

### 암호화 방식

- **비대칭 암호화**: 초기 핸드셰이크에서 대칭키 교환용
- **대칭 암호화**: 실제 데이터 통신에서 사용 (속도가 빠름)
- **해시 함수**: 데이터 무결성 검증용

## SSL/TLS 인증서 검증 과정

인증서 검증은 **신뢰 체인(Chain of Trust)**을 통해 이루어집니다.

### 인증서 구조
```
Root CA (루트 인증기관)
└── Intermediate CA (중간 인증기관)
    └── Server Certificate (서버 인증서)
```

### 검증 단계

**1단계: 인증서 체인 검증**
- 서버가 자신의 인증서와 중간 CA 인증서를 함께 전송
- 클라이언트는 중간 CA → 루트 CA 순서로 서명을 검증
- 루트 CA는 브라우저/OS에 미리 설치되어 있음

**2단계: 디지털 서명 검증**
- 상위 CA의 공개키로 하위 인증서의 서명을 복호화
- 복호화된 해시값과 인증서 내용의 해시값이 일치하는지 확인

**3단계: 인증서 유효성 검사**
- 유효기간 확인
- 도메인 이름 매칭 (CN 또는 SAN 필드)
- 인증서 폐기 목록(CRL) 또는 OCSP로 폐기 여부 확인

### 디지털 서명에서의 활용
```
1. 문서 → 해시 함수 → 해시값
2. 해시값 + 개인키 → 디지털 서명
3. 서명 + 공개키 → 해시값 복구
4. 원본 문서의 해시값과 비교
```

## 대칭 암호화 vs 비대칭 암호화

### 대칭 암호화 (Symmetric Encryption)
- **같은 키**로 암호화와 복호화를 수행
- **장점**: 매우 빠름 (AES 등)
- **단점**: 키를 안전하게 공유하는 문제

```
평문 + 비밀키 → 암호문
암호문 + 같은 비밀키 → 평문
```

### 비대칭 암호화 (Asymmetric Encryption)
- **공개키**와 **개인키** 한 쌍을 사용
- 공개키로 암호화 → 개인키로 복호화
- 개인키로 서명 → 공개키로 검증
- **장점**: 키 공유 문제 해결
- **단점**: 느림 (RSA, ECDSA 등)

```
평문 + 공개키 → 암호문
암호문 + 개인키 → 평문
```

### SSL/TLS에서의 활용
1. **비대칭 암호화**: 핸드셰이크에서 대칭키를 안전하게 교환
2. **대칭 암호화**: 실제 데이터 통신 (속도 때문)

## 해시 함수의 역할과 맥락

SSL/TLS에서 해시 함수는 여러 용도로 사용됩니다:

### 데이터 무결성 검증
```
원본 데이터 → 해시 함수 → 고정 길이 해시값
```
- 데이터가 전송 중 변조되었는지 확인
- 같은 데이터는 항상 같은 해시값 생성
- 조금이라도 다르면 완전히 다른 해시값

### HMAC (Hash-based Message Authentication Code)
```
데이터 + 비밀키 → HMAC → 인증 코드
```
- 메시지 인증과 무결성을 동시에 보장
- 송신자가 올바른 비밀키를 가지고 있음을 증명

### SSL/TLS Record에서 사용
각 SSL/TLS 레코드는 다음과 같은 구조를 가집니다:
```
[헤더][암호화된 데이터][MAC(해시 기반 인증 코드)]
```

**예시**: HTTPS로 웹페이지를 받을 때
1. 서버가 HTML 데이터의 해시값을 계산
2. 대칭키로 데이터와 해시값을 함께 암호화
3. 클라이언트가 복호화 후 해시값을 재계산하여 비교
4. 일치하면 데이터가 변조되지 않았음을 확인

## HTTP(S)와 WebSocket과의 차이점

### HTTP/HTTPS 특징
- **요청-응답 모델**: 클라이언트가 요청하면 서버가 응답
- **상태 없음(Stateless)**: 각 요청은 독립적
- **단방향 통신**: 클라이언트가 먼저 요청해야 함
- **연결 해제**: 응답 후 연결이 종료됨 (HTTP/1.1에서는 Keep-Alive 가능)

### WebSocket 특징
- **전이중 통신**: 클라이언트와 서버가 동시에 데이터 전송 가능
- **상태 유지(Stateful)**: 연결이 유지되는 동안 상태 보존
- **실시간 통신**: 서버가 먼저 클라이언트에게 데이터 전송 가능
- **지속적 연결**: 한 번 연결되면 명시적으로 끊을 때까지 유지

### 사용 사례
- **HTTP/HTTPS**: 일반적인 웹 페이지, REST API, 파일 다운로드
- **WebSocket**: 채팅 애플리케이션, 실시간 게임, 주식 거래 시스템, 라이브 스트리밍

### WebSocket과 보안
WebSocket도 보안을 위해 **WSS (WebSocket Secure)**를 사용할 수 있으며, 이는 WebSocket over TLS/SSL을 의미합니다. HTTP에서 HTTPS로의 관계와 동일합니다.

## OSI 7계층 모델

OSI 7계층은 네트워크 통신을 7개의 논리적 계층으로 나눈 표준 모델입니다. 각 계층은 독립적인 역할을 가지며, 하위 계층에서 상위 계층으로 데이터가 전달됩니다.

### 7계층 - 응용 계층 (Application Layer)
**역할**: 사용자가 직접 상호작용하는 계층
- **프로토콜**: HTTP, HTTPS, FTP, SMTP, DNS, SSH
- **예시**: 웹 브라우저, 이메일 클라이언트, 파일 전송 프로그램
- **데이터**: 실제 사용자 데이터

### 6계층 - 표현 계층 (Presentation Layer)
**역할**: 데이터 형식 변환, 암호화/복호화, 압축
- **기능**: 문자 인코딩, 데이터 압축, SSL/TLS 암호화
- **예시**: JPEG, GIF, ASCII, 압축 알고리즘
- **데이터**: 포맷된 데이터

### 5계층 - 세션 계층 (Session Layer)
**역할**: 통신 세션 관리 (연결 설정, 유지, 종료)
- **기능**: 세션 체크포인트, 동기화, 대화 제어
- **프로토콜**: NetBIOS, RPC, SQL 세션
- **예시**: 로그인 세션, 데이터베이스 연결

### 4계층 - 전송 계층 (Transport Layer)
**역할**: 신뢰성 있는 데이터 전송, 흐름 제어
- **프로토콜**: TCP, UDP
- **기능**: 포트 번호 관리, 오류 복구, 순서 보장
- **데이터**: 세그먼트 (Segment)

### 3계층 - 네트워크 계층 (Network Layer)
**역할**: 라우팅, 경로 설정
- **프로토콜**: IP, ICMP, ARP, OSPF
- **장비**: 라우터
- **데이터**: 패킷 (Packet)
- **주소**: IP 주소

### 2계층 - 데이터 링크 계층 (Data Link Layer)
**역할**: 같은 네트워크 내에서 노드 간 신뢰성 있는 전송
- **프로토콜**: Ethernet, Wi-Fi, PPP
- **장비**: 스위치, 브리지
- **데이터**: 프레임 (Frame)
- **주소**: MAC 주소

### 1계층 - 물리 계층 (Physical Layer)
**역할**: 전기적 신호로 비트 전송
- **매체**: 케이블, 광섬유, 무선
- **장비**: 허브, 리피터, 케이블
- **데이터**: 비트 (Bit)

## 데이터 전송 과정

### 송신 과정 (캡슐화)
```
7계층: 사용자 데이터
6계층: 데이터 + 표현 헤더
5계층: 데이터 + 세션 헤더
4계층: 데이터 + TCP/UDP 헤더 = 세그먼트
3계층: 세그먼트 + IP 헤더 = 패킷
2계층: 패킷 + Ethernet 헤더 = 프레임
1계층: 프레임 → 전기 신호
```

### 수신 과정 (역캡슐화)
```
1계층: 전기 신호 → 프레임
2계층: 프레임에서 Ethernet 헤더 제거 = 패킷
3계층: 패킷에서 IP 헤더 제거 = 세그먼트
4계층: 세그먼트에서 TCP/UDP 헤더 제거 = 데이터
5계층: 세션 헤더 제거
6계층: 표현 헤더 제거
7계층: 사용자 데이터
```

## TCP/IP 모델과의 비교

OSI 7계층은 이론적 모델이고, 실제로는 **TCP/IP 4계층 모델**이 더 많이 사용됩니다:

- **응용 계층**: OSI 5,6,7계층 통합
- **전송 계층**: OSI 4계층과 동일
- **인터넷 계층**: OSI 3계층과 동일  
- **네트워크 접근 계층**: OSI 1,2계층 통합

## 실제 예시: 웹 브라우징

1. **7계층**: 브라우저에서 HTTP 요청 생성
2. **6계층**: HTTPS라면 SSL/TLS 암호화
3. **5계층**: HTTP 세션 관리
4. **4계층**: TCP로 데이터를 세그먼트로 분할, 포트 80/443 사용
5. **3계층**: IP 헤더 추가, 라우터에서 경로 결정
6. **2계층**: Ethernet 프레임으로 포장, MAC 주소 사용
7. **1계층**: 네트워크 케이블을 통해 전기 신호로 전송

## 마무리

현대 웹 개발에서는 보안상의 이유로 HTTPS 사용이 필수가 되었으며, 많은 브라우저에서 HTTP 사이트에 대해 "안전하지 않음" 경고를 표시합니다. OSI 7계층 모델은 복잡한 네트워크 통신을 체계적으로 이해할 수 있게 도와주는 참조 모델로, 네트워크 문제 해결이나 시스템 설계 시 유용한 프레임워크를 제공합니다.
