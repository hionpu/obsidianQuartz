# AI 에게 `ctags` 로 효율적인 코드 컨텍스트 제공하기

AI와 함께 코딩하는 것은 생산성을 크게 높여줄 수 있지만, 때로는 AI가 이미 존재하는 파일을 제안하거나, 데이터 구조의 인터페이스를 제대로 이해하지 못해 엉뚱한 코드를 작성하는 문제가 발생하기도 합니다. 이는 AI가 현재 프로젝트의 전체 구조와 세부적인 메서드 시그니처를 정확히 알지 못하기 때문에 생기는 흔한 문제입니다.

저 또한 AI와의 협업에서 이런 답답함을 겪곤 했습니다. 전체 프로젝트 코드를 AI에게 다 보여주자니 너무 많은 토큰을 소모하고, 관련 없는 파일까지 전달되어 오히려 혼란을 가중시킬 때도 있었죠. 하지만 `ctags`를 활용하면서 이 문제를 효과적으로 해결할 수 있었습니다. 오늘은 `ctags`를 사용해 AI에게 최적의 프로젝트 컨텍스트를 제공하는 방법을 공유합니다.

---

## AI 페어 프로그래밍의 흔한 문제점

AI 페어 프로그래밍 시 다음과 같은 상황에 부딪힌 적이 있다면, 여러분도 같은 문제에 직면하고 있는 겁니다.

1. **중복 코드 제안**: AI가 이미 구현된 파일이나 함수를 다시 만들라고 제안하는 경우.
    
2. **인터페이스 불일치**: AI가 프로젝트의 기존 데이터 구조나 함수 인터페이스(메서드 시그니처, 파라미터)를 정확히 파악하지 못해, 현재 코드와 호환되지 않는 로직을 제안하는 경우.
    
3. **불필요한 토큰 소모**: 문제 해결을 위해 전체 코드를 AI에게 입력하다 보니, 막대한 토큰 비용이 발생하고 AI의 응답 속도도 느려지는 경우.
    

이 모든 문제는 AI가 "현재 프로젝트 상태"에 대한 **정확하고 간결한 이해**가 부족하기 때문에 발생합니다.

---

## `ctags`가 AI 컨텍스트 문제 해결에 도움을 준 방법

`ctags`는 소스 코드 파일에서 함수 정의, 변수 선언, 클래스 이름 등 다양한 프로그래밍 언어 객체에 대한 인덱스(`tags` 파일)를 생성하는 강력한 커맨드라인 도구입니다. 원래는 `Vim`과 같은 텍스트 에디터에서 코드 탐색을 돕는 데 주로 사용되었죠.

저는 이 `ctags`의 기능을 AI에게 **프로젝트의 뼈대(skeleton)**를 제공하는 데 활용했습니다.

### 1. **핵심 정보만 추출하여 토큰 절약**

`ctags`는 함수나 메서드의 이름, 파일 경로, 그리고 **메서드 시그니처(이름과 파라미터)** 정보를 추출할 수 있습니다. 저는 이 기능을 활용하여 실제 함수 본문 내용은 제외하고, 메서드 이름과 파라미터 정보만 AI에게 전달했습니다. 이는 AI가 전체 코드 더미를 읽는 것보다 훨씬 적은 토큰으로 프로젝트의 주요 인터페이스를 파악하는 데 결정적인 역할을 했습니다.

### 2. **정확한 인터페이스 이해 유도**

메서드 시그니처와 파라미터 정보를 제공함으로써 AI는 특정 함수가 어떤 인자를 받고 어떤 역할을 하는지 명확히 인지하게 됩니다. 덕분에 AI는 기존 코드와 호환되는 새로운 코드를 제안하거나, 이미 존재하는 기능을 다시 만들라고 제안하는 실수를 줄일 수 있었습니다. 마치 AI에게 프로젝트의 '목차'와 '각 장의 소제목'을 정확히 알려주는 것과 같았습니다.

### 3. **개발 효율성 향상**

AI가 프로젝트 구조를 잘 이해하게 되면서, 저의 역할은 AI가 제공한 아이디어를 검토하고 필요한 부분을 조정하는 데 집중할 수 있게 되었습니다. 불필요한 중복 작업이나 인터페이스 불일치로 인한 시행착오가 줄어들어 전반적인 개발 속도가 향상되었습니다.

## `ctags`를 사용한 프로젝트 컨텍스트 추출 및 활용 가이드

이제 `ctags`를 설치하고 AI에게 제공할 프로젝트 구조를 추출하는 방법을 자세히 알아볼까요?

### 1. `ctags` 설치하기 (Universal Ctags 권장)

대부분의 운영체제에서 패키지 관리자를 통해 쉽게 설치할 수 있습니다.

- **macOS (Homebrew):**
    
    Bash
    
    ```
    brew install universal-ctags/universal-ctags/universal-ctags
    ```
    
- **Linux (Debian/Ubuntu):**
    
    Bash
    
    ```
    sudo apt-get update
    sudo apt-get install universal-ctags
    ```
    
- **Windows (Chocolatey):**
    
    PowerShell
    
    ```
    choco install universal-ctags
    ```
    
    (수동 설치 방법은 공식 문서를 참고하세요.)
    

### 2. 프로젝트 태그 생성하기

프로젝트 루트 디렉토리로 이동하여 다음 명령어를 실행합니다:

Bash

```
ctags -R . --exclude=node_modules --exclude=.git --exclude=build --output-format=json > project_skeleton.json
```

- `-R .`: 현재 디렉토리와 모든 하위 디렉토리를 재귀적으로 탐색합니다.
    
- `--exclude=...`: `node_modules`, `.git`, `build` 등 태그 생성이 불필요하거나 용량이 큰 디렉토리를 제외합니다. 이는 토큰 절약에 매우 중요합니다.
    
- `--output-format=json`: 태그 정보를 JSON 형식으로 출력합니다. 이 형식은 AI가 파싱하기에 훨씬 용이합니다. (기본 출력은 `tags` 파일이며, 이는 에디터용입니다.)
    
- `> project_skeleton.json`: 추출된 정보를 `project_skeleton.json` 파일로 리다이렉트합니다.
    

**팁:** `--output-format=json` 옵션은 Universal Ctags의 비교적 최신 기능입니다. 만약 오류가 발생한다면, `ctags -x -R . > project_skeleton.txt`를 사용하여 크로스-레퍼런스 형태로 텍스트 파일을 만들고, 이를 가공하는 스크립트를 작성하는 방법도 있습니다. 하지만 JSON이 AI에게 더 효율적입니다.

### 3. AI에게 컨텍스트 제공하기

생성된 `project_skeleton.json` 파일을 열어 내용을 확인합니다. 이 파일에는 각 함수의 이름, 파일 경로, 그리고 시그니처 정보 등이 포함되어 있습니다.

이제 새로운 AI 채팅을 시작할 때, 이 `project_skeleton.json` 파일의 내용을 복사하여 AI에게 제공합니다. 예를 들어, 다음과 같이 서두를 시작할 수 있습니다.

```
안녕하세요! 저는 현재 [프로젝트명] 프로젝트를 개발 중입니다. 이 프로젝트의 주요 구조와 메서드 시그니처는 다음과 같습니다. 이 정보를 바탕으로 제가 요청하는 작업에 대한 제안을 해주세요.

[여기에 project_skeleton.json 파일의 내용 전체를 복사 붙여넣기]

이제 제가 작업하려는 내용은 [구체적인 작업 내용] 입니다. 어떤 방식으로 구현하면 좋을까요?
```

저는 별도의 프로젝트 오버뷰 .md 파일을 제공하고 있어요.
