# 데이터베이스 인덱스와 B-Tree 구조

## 데이터베이스 인덱스란?

데이터베이스 인덱스는 테이블의 데이터에 대한 **빠른 검색을 위한 추가적인 데이터 구조**입니다. 책의 색인(index)과 같은 역할을 하며, 특정 값을 찾기 위해 전체 테이블을 스캔하지 않고도 원하는 데이터를 빠르게 찾을 수 있게 해줍니다.

## 인덱스의 동작 원리

### 1. 인덱스 없는 경우 (Full Table Scan)
```
SELECT * FROM users WHERE age = 25;
```
- 테이블의 모든 행을 순차적으로 검사
- 시간 복잡도: O(n)
- 데이터가 많을수록 성능 저하

### 2. 인덱스 있는 경우
```sql
CREATE INDEX idx_age ON users(age);
SELECT * FROM users WHERE age = 25;
```
- 인덱스를 통해 해당 값의 위치를 빠르게 파악
- 시간 복잡도: O(log n)
- 대용량 데이터에서도 빠른 검색

## B-Tree 구조란?

**B-Tree(B-트리)**는 데이터베이스 인덱스에서 가장 널리 사용되는 자료구조입니다.

### B-Tree의 특징

1. **균형 트리**: 모든 리프 노드가 같은 레벨에 위치
2. **다진 트리**: 하나의 노드가 여러 개의 키를 가질 수 있음
3. **정렬된 구조**: 노드 내의 키들이 정렬되어 있음
4. **범위 검색에 효율적**: 순차적 접근이 가능

### B-Tree 노드 구조

```
[키1 | 포인터1 | 키2 | 포인터2 | ... | 키n | 포인터n+1]
```

- **키**: 실제 인덱스 값
- **포인터**: 자식 노드 또는 데이터 페이지를 가리킴
- **차수(Order)**: 한 노드가 가질 수 있는 최대 자식 수

### B-Tree 검색 과정

1. **루트 노드**에서 시작
2. 찾는 값과 노드의 키들을 **비교**
3. 적절한 **자식 노드로 이동**
4. **리프 노드**에 도달할 때까지 반복
5. 리프 노드에서 **실제 데이터 위치** 확인

## B-Tree가 사용되는 이유

### 1. 디스크 I/O 최적화
- 데이터베이스는 주로 디스크에 저장
- B-Tree는 **한 번의 디스크 읽기로 여러 키를 확인** 가능
- 디스크 접근 횟수 최소화

### 2. 범위 검색 효율성
```sql
SELECT * FROM users WHERE age BETWEEN 20 AND 30;
```
- B-Tree의 **순차적 구조**로 범위 검색이 효율적
- 리프 노드들이 **연결 리스트**로 연결되어 있음

### 3. 삽입/삭제 시 균형 유지
- 데이터 삽입/삭제 시에도 **자동으로 균형** 유지
- 항상 O(log n)의 검색 성능 보장

## B-Tree의 변형들

### B+Tree
- **리프 노드에만 실제 데이터** 저장
- 내부 노드는 **인덱스 역할**만 수행
- 리프 노드들이 **순차적으로 연결**
- 대부분의 RDBMS에서 사용

### B\*Tree
- 노드 **분할을 지연**시켜 공간 효율성 향상
- 노드 사용률이 더 높음

## 인덱스 사용 시 고려사항

### 장점
- **검색 성능 대폭 향상**
- **정렬된 결과** 빠르게 획득
- **범위 검색** 효율적

### 단점
- **추가 저장 공간** 필요
- **삽입/수정/삭제 시 오버헤드** 발생
- **메모리 사용량** 증가

### 인덱스 생성 가이드라인

1. **자주 검색되는 컬럼**에 생성
2. **카디널리티가 높은 컬럼** 우선
3. **조인 조건**으로 사용되는 컬럼
4. **ORDER BY, GROUP BY**에 사용되는 컬럼

## 실제 사용 예시

```sql
-- 인덱스 생성
CREATE INDEX idx_user_email ON users(email);
CREATE INDEX idx_order_date ON orders(order_date);

-- 복합 인덱스
CREATE INDEX idx_user_age_city ON users(age, city);

-- 인덱스 사용 확인
EXPLAIN SELECT * FROM users WHERE email = 'test@example.com';
```

## 마무리

B-Tree 구조의 인덱스는 데이터베이스 성능 최적화의 핵심 요소입니다. 디스크 기반 저장소의 특성을 고려한 설계로, 대용량 데이터에서도 일관된 성능을 제공합니다. 적절한 인덱스 설계는 애플리케이션의 성능을 크게 향상시킬 수 있습니다.
