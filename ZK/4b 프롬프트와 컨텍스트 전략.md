# 4b 프롬프트와 컨텍스트 전략

핵심 통찰: **모호한 프롬프트는 그럴싸하지만 틀린 결과를 낳는다.**
구체적이고 구조화된 프롬프트 = 재작업 없는 결과.

## 좋은 프롬프트의 구조

```
1. 역할/컨텍스트: "이 코드는 WPF MVVM 프로젝트다"
2. 목표: "UserService의 LoginAsync를 구현해라"
3. 제약: "DI로 주입된 IUserRepository만 사용, 예외 처리 포함"
4. 계약: "반환 타입은 Result<User>, 실패 시 LoginError"
5. 검증: "기존 테스트를 통과해야 한다"
```

## 토큰 효율 전략

| 전략 | 효과 |
|------|------|
| ctags로 심볼만 제공 | 파일 전체 대신 구조만 → 80% 절약 |
| caveman 압축 | 대화 히스토리 요약 → 세션 연장 |
| 서브에이전트 분리 | 복잡한 태스크를 독립 컨텍스트로 → 메인 세션 보호 |

## TDD와의 연결
계약(Contract)이 명확하면 프롬프트도 명확해진다.
→ [[2a TDD와 Contract-First]]의 계약이 최고의 프롬프트다.
