# 5b 게임 개발 사이클

핵심 원칙: **완성된 게임 하나가 기획 10개보다 낫다.**
1인 개발의 가장 큰 위험 = 미완성 프로젝트 누적.

## 5-사이클 마스터 플랜

각 사이클은 독립적으로 완결된 소규모 게임을 목표로 한다.
- 사이클 1: 약초꾼 시뮬레이터 (첫 번째 완성 목표)
- 이후 사이클은 이전 사이클의 학습을 기반으로 확장

## 사이클 단위 작업 흐름

```
컨셉 정의 → 핵심 루프 프로토타입 → 수직 슬라이스 → 완성 → 출시/공개
```

각 단계에서 "이게 재미있는가?"를 먼저 검증. 재미 없으면 컨셉 단계로 돌아가거나 사이클 포기.

## 세계관 설계의 역할
세계관 = 창작의 제약 조건.
좋은 제약은 의사결정을 빠르게 만든다: "이 게임 세계관에서 이게 말이 되는가?"
→ 범위 크리프(scope creep) 방지.

## 엔지니어링 연결
게임 개발 = Contract-First이 특히 효과적인 영역.
게임 규칙 = 불변식(Invariant).
→ [[2a TDD와 Contract-First]]의 Unity 버전으로 연결.
