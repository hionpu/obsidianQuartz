# 2c 성능 최적화

핵심 원칙: **UI 스레드는 절대 블로킹하지 않는다.**
그 다음 원칙: **측정하기 전에 최적화하지 않는다.**

## UI 스레드 블로킹 패턴

### 잘못된 패턴
```csharp
// UI 스레드에서 직접 무거운 작업
void Button_Click() {
    var result = HeavyComputation(); // UI 멈춤
    label.Text = result;
}
```

### 올바른 패턴
```csharp
async void Button_Click() {
    var result = await Task.Run(() => HeavyComputation()); // 백그라운드
    label.Text = result; // UI 스레드로 복귀 후 업데이트
}
```

## WriteableBitmap 최적화
고해상도 이미지를 WPF에서 직접 픽셀 조작할 때:
- `WriteableBitmap.Lock()` → 픽셀 버퍼 접근
- 배치로 픽셀 쓰고 → `AddDirtyRect()` → `Unlock()`
- 매 프레임 전체 재생성 금지 → 변경된 영역만 업데이트

## 이미지 렌더링 Stuttering 원인
- 고해상도 이미지를 매 프레임 `BitmapImage`로 재생성 → GC 압력
- 해결: 이미지 캐싱, `RenderOptions.BitmapScalingMode` 조정
