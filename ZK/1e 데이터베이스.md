# 1e 데이터베이스

핵심 통찰: **인덱스 = 읽기 속도를 위해 쓰기 비용을 지불하는 구조.**
인덱스를 많이 걸수록 SELECT는 빠르지만 INSERT/UPDATE/DELETE가 느려진다.

## B-Tree 인덱스가 기본인 이유
- 디스크는 순차 접근이 빠름 → 정렬된 B-Tree가 유리
- 범위 쿼리(`WHERE age BETWEEN 20 AND 30`)에 효율적
- 해시 인덱스는 등치 비교만 가능, 범위 불가

## 인덱스 설계 원칙
1. **카디널리티가 높은 컬럼**에 인덱스 — 성별(2가지)보다 이메일(수백만 가지)이 효과적
2. **복합 인덱스는 순서가 중요** — `(A, B)` 인덱스는 A 단독 조건엔 쓸 수 있지만 B 단독엔 못 씀
3. **SELECT가 많은 컬럼** 우선 — OLTP는 읽기 중심이면 인덱스 적극 활용

## SQLAlchemy 연결
ORM이 쿼리를 어떻게 생성하는지 알아야 인덱스가 효과를 발휘하는지 확인 가능.
→ [[3b Python Flask]]의 SQLAlchemy 패턴으로 연결.
