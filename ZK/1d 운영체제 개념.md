# 1d 운영체제 개념

핵심 통찰: **프로세스 = 격리된 자원 컨테이너. 스레드 = 그 안의 실행 단위.**
이 구분이 멀티태스킹의 모든 트레이드오프를 설명한다.

## 프로세스 vs 스레드

| | 프로세스 | 스레드 |
|---|---------|--------|
| 메모리 공간 | 독립 (격리) | 공유 (같은 프로세스 내) |
| 생성 비용 | 높음 | 낮음 |
| 통신 방식 | IPC (파이프, 소켓) | 공유 메모리 (동기화 필요) |
| 장애 격리 | 다른 프로세스에 영향 없음 | 스레드 하나 죽으면 프로세스 전체 위험 |

## 컨텍스트 스위칭
CPU가 실행 중인 태스크를 바꿀 때 현재 상태(레지스터, 프로그램 카운터 등)를 저장하고 다음 태스크 상태를 복원하는 과정.

비용이 0이 아니다 — 스레드가 너무 많으면 스위칭 비용이 실제 작업보다 커진다.

## 실무 연결
WPF에서 UI 스레드를 블로킹하면 안 되는 이유:
메인 스레드 = UI 렌더링 스레드. 블로킹 → 앱 멈춤.
→ [[3a C# WPF]]의 Dispatcher 패턴으로 연결.
