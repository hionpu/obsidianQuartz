# 📥 inbox 처리 워크플로우

> 이 폴더 = **떠오른 생각을 0.5초 안에 던지는 임시 그물.**
> 쌓이는 곳이 아니라 **통과하는 곳.** 처리 후 inbox는 비어 있어야 정상.

---

## 캡처 (운동 중 / 이동 중 / 자기 전, 주로 모바일)

- 모바일 Obsidian에서 새 노트 → **한 줄 쓰고 끝.** 템플릿·태그·제목 신경 X.
- 분야 무관. 코드든 영상 아이디어든 게임이든 다 여기로.
- 파일명도 대충 (앞부분 몇 글자 자동이면 됨).
- 다 쓰면 git sync (모바일 → PC 자동 반영).

예시:
```
인트로 길면 이탈하더라
약초꾼 게임에 날씨 시스템?
Elixir GenServer 상태 영속화 방법 찾기
```

---

## 처리 (PC에서, 정해진 주기에 — 예: 하루 한 번 5분)

`inbox/`의 메모를 하나씩 보며 **3가지 중 하나**로 결정:

| 판단 | 행동 |
|------|------|
| 🟢 쓸만한 아이디어 | → `ZK/`에 permanent note로 **내 말로 재구성** → inbox 원본 **삭제** |
| 🟡 자료 / 할 일 / 링크 | → 알맞은 곳(`content/`, 할일앱 등)으로 이동 → inbox에서 제거 |
| 🔴 별로 / 이미 있음 | → 그냥 **삭제** |

**핵심: inbox를 비우는 게 목표.** 노트를 남기는 게 아니라 흘려보내는 것.

---

## 언제까지 처리하나

숫자 규칙(48시간 등)은 신경 X. 진짜 기준:

> **"이게 뭐였더라?" 상태가 되기 전에 처리하라.**

기억이 살아있는 동안 소화. 보통 1~2일. 본인 리듬대로 (매일 저녁이든 주말 몰아서든).

---

## 원칙 한 줄
**inbox는 통과하는 곳이지 쌓이는 곳이 아니다.**
처리 안 된 메모가 쌓이면 → 죄책감 더미 + 검색 오염. 비우지 못할 바엔 과감히 삭제.

## 🤖 AI에게 처리 맡기기 (zero-context 새 세션용 프롬프트)

> AI는 **기계적 구조화(트리아지·ID 부여·골격 작성·연결 검색)만** 담당한다.
> 의미 확정·삭제는 사람 몫. 아래 프롬프트를 새 채팅에 그대로 붙여넣어 사용.

```
inbox/ 폴더의 fleeting note들을 ZK permanent note로 승격하는 작업을 도와줘.
이 vault는 Folgezettel 방식 Zettelkasten이야. 아래 규칙과 절차를 정확히 따라.

## vault 구조
- ZK/         = 영구 노트. 파일명 "[id] [제목].md". Folgezettel ID: 1 → 1a → 1a1, 형제는 1a → 1b
- content/    = 기존 장문 레퍼런스(literature) 노트 (type: reference)
- ZK-Index/   = 키워드 인덱스(선택적, 건드리지 마)
- inbox/      = 지금 처리할 fleeting note들 (밑줄 _ 로 시작하는 파일은 제외)
- 구조 파악 도구 (ZK 노트 전부 읽지 말 것):
  - `inbox/_zk-tree.ps1 [id]` = 노드의 직속 자식만 반환 (부모 찾기·빈 ID 확인용)
  - `inbox/_zk-map.md` = 전체 평맵 (소규모 조망용, `_zk-map 생성.ps1`로 갱신)

## 영구 노트 frontmatter
id / type: permanent / up: "[[상위노트]]" / created / tags

## 절차
**토큰 절약 원칙: ZK 노트를 전부 읽지 마.** 두 도구를 나눠 쓴다.
- **부모 찾기 → 트리 lazy 탐색** (`inbox/_zk-tree.ps1`): 위에서 아래로 필요한 가지만.
- **연결 찾기 → 키워드 grep** (가로 검색): 연결은 계층이 아니라 주제로 이어진다.

1. inbox/ 의 _ 안 붙은 메모를 전부 읽는다.
2. 각 메모를 트리아지:
   🟢 재사용 가능한 아이디어 → ZK 승격 후보
   🟡 자료/할일/영상아이디어 → 적절한 폴더로 이동 후보 (예: content/018-YouTube/004_idea/)
   🔴 의미 없음/중복 → 삭제 후보
3. 🟢 각각에 대해:
   a. **부모 결정 (트리 탐색)**:
      - `pwsh "inbox/_zk-tree.ps1"` → 루트 목록 확인, 어느 가지인지 고른다.
      - `pwsh "inbox/_zk-tree.ps1" <id>` → 그 가지 자식만 본다. 필요하면 ▸ 따라 한 단계 더.
      - 적절한 부모를 찾고 **빈 자식 ID 부여** (그 부모의 자식 목록에서 다음 빈 글자/번호).
      - ⚠️ 루트~목표 가지 외의 다른 가지는 열지 마.
   b. **노트 골격 작성**:
      - 제목 아래 "핵심 문장 한 줄"을 **재사용 가능한 교훈** 형태로
      - 본문은 메모 내용을 풀어서 구조화 (원인/개선, 정의/예시 등)
      - tags 제안 (부모 태그와 일관되게 — 트리 출력의 #tags 참고)
   c. **연결 찾기 (grep)**:
      - 메모의 핵심 키워드로 `ZK/`·`content/`를 Grep (예: "에임", "이탈", "인덱스").
      - 걸린 노트만 한 줄 확인 후 `## 연결`에 링크. 억지 연결 금지, 없으면 비움.
      - 트리에서 만난 부모/형제도 자연스러우면 링크.
4. (선택) 큰 그림이 필요하면 평맵: `pwsh "inbox/_zk-map 생성.ps1"` → `inbox/_zk-map.md` 한 번에 조망.
   ※ 노트 100개 미만이면 평맵 한 방이 더 쌀 수도 있음. 규모 보고 판단.

## 반드시 지킬 안전장치
- **fleeting note는 압축이 심해 의미를 추측하기 쉽다. 조금이라도 모호하면 추측하지 말고 나에게 먼저 질문해.**
- **inbox 원본을 절대 삭제하지 마.** 내가 검토하고 직접 지운다.
- 먼저 트리아지 표 + 각 🟢 노트의 제안(제목/핵심문장/위치/연결)을 보여주고, 내 승인을 받은 뒤에만 ZK/ 에 파일을 만들어.
- 만든 뒤에도 원본은 그대로 두고, "검토 후 직접 삭제하라"고 알려줘.
```

### 왜 전자동이 아닌가
fleeting note는 한두 단어로 압축돼 있어 AI가 의도를 빗나갈 수 있다. (실제로 '도망가지 않기'를
처음엔 다르게 해석했다가 바로잡은 적 있음.) **생각의 소유권은 사람**, AI는 골격만 — 이게 ZK가
망가지지 않는 선이다.
