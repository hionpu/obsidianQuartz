> [!assistant]+
> 승우님의 질문처럼, [[RESTful API 설계 원칙과 아키텍처]] 파일에서 설명하는 REST의 **무상태성(Stateless)** 원칙과 [[JWT와 세션 인증 방식 비교]] 파일에서 설명하는 **세션 기반 인증**의 상태 유지(Stateful) 방식은 **서로 상충되는 개념이 맞습니다.**
> 
> *   **REST의 무상태성:** 서버는 클라이언트의 요청 간 상태 정보를 저장하지 않습니다. 각 요청은 독립적으로 처리되며, 필요한 모든 정보(인증 정보, 세션 정보 등)는 요청 자체에 포함되어야 합니다. 이 원칙은 서버의 확장성, 신뢰성, 단순성을 높이는 데 기여합니다.
> *   **세션 기반 인증:** 사용자가 로그인하면 서버는 해당 사용자를 위한 세션을 생성하고 서버 측 메모리나 데이터베이스에 저장합니다. 클라이언트에게는 이 세션을 식별할 수 있는 세션 ID만 발급하고, 클라이언트는 이후 요청 시 세션 ID를 쿠키 등을 통해 서버에 전달합니다. 서버는 이 세션 ID를 이용해 저장된 사용자 상태 정보를 조회합니다. 이는 서버가 상태를 **기억하고 유지**하는 **Stateful** 방식입니다.
> 
> 따라서, 순수하게 RESTful 아키텍처의 무상태성 원칙을 엄격히 따른다면 세션 기반 인증은 적합하지 않습니다. RESTful API는 클라이언트가 요청에 모든 필요한 정보를 담아 보내고, 서버는 단순히 그 요청만 처리하여 응답하는 방식에 기반하기 때문입니다.
> 
> [[JWT와 세션 인증 방식 비교]] 파일에서도 설명하듯, JWT와 같은 토큰 기반 인증 방식이 REST의 무상태성 원칙에 더 부합합니다. JWT는 토큰 자체에 사용자 정보(payload)를 포함하고 있으며, 서버는 해당 토큰의 유효성만 검증하면 되기 때문에 별도로 클라이언트의 상태를 서버에 저장할 필요가 없습니다.
> 
> 실제 시스템 설계에서는 서비스의 특성, 보안 요구사항, 확장성 등을 종합적으로 고려하여 두 방식 중 하나를 선택하거나, 때로는 두 방식을 조합한 하이브리드 형태를 사용하기도 합니다. 예를 들어, 전통적인 웹 애플리케이션에서는 세션이 편리할 수 있고, 마이크로서비스나 분산 시스템에서는 무상태성을 지향하는 JWT가 더 유리합니다.
